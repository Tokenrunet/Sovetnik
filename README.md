# Liquidity Sweep Pro (MT4)

Советник `LiquiditySweep_Pro.mq4` торгует ложные пробои (снятие ликвидности, SMC). Он заменяет мартингейл-версию `Liquidity_Sweep_SMC_Improved`.

## Логика

1. **Свип.** Закрытый бар прокалывает максимум или минимум за `RangePeriod` баров и закрывается обратно внутри диапазона.
2. **Подтверждение.** В течение `ConfirmBars` баров должен закрыться бар за противоположным краем бара-свипа: для SELL ниже его Low, для BUY выше его High. Если за это время экстремум свипа обновился, сетап отменяется.
3. **Вход.** Позиция открывается на открытии следующего бара.
   - SL ставится за экстремум свипа плюс `SLBufferATR × ATR`.
   - TP равен риску, умноженному на `RewardRatio`.
4. **Сопровождение.** При прибыли `BreakevenAtR × R` стоп переносится в безубыток. Частичное закрытие, трейлинг по ATR и выход по времени есть, но по умолчанию выключены.
5. **Риск.** Одна позиция за раз. Лот рассчитывается так, чтобы срабатывание SL стоило `RiskPercent`% баланса. Мартингейла и усреднения нет.

## Чем отличается от старой версии

| | Старая версия | Liquidity Sweep Pro |
|---|---|---|
| Стоп-лосс | нет, только виртуальный | настоящий, за фитилём свипа |
| Объём | мартингейл, до 13+ слоёв | один ордер, фиксированный % риска |
| Сигнал | на незакрытом баре 0, каждый тик | только по закрытому бару, раз в бар |
| Закрытие | по неверной цене (Ask/Bid перепутаны) | `Bid` для BUY, `Ask` для SELL, повторы при реквотах |
| Лот | без шага лота и min/max | шаг, min/max, проверка маржи |
| Защита счёта | нет | дневной лимит, стоп по просадке, закрытие в пятницу |
| Лог | несколько `Print` на каждом тике | только сделки и пропуски входа |

## Как тестировать

1. Скопируйте `LiquiditySweep_Pro.mq4` в `Файл → Открыть каталог данных → MQL4/Experts` и скомпилируйте в MetaEditor (F7). Ошибок быть не должно.
2. В «Сервис → Архив котировок» (F2) загрузите историю EURUSD минимум за 3 года.
3. Настройки тестера:
   - символ `EURUSD.fx`, период **H1**;
   - модель **«Все тики»**;
   - спред **20** (как на вашем счёте) или «текущий»;
   - даты: например, 2022-01-01 – 2026-10-01.
4. Сначала прогон с параметрами по умолчанию. Смотрите:
   - **профит-фактор** (нужно > 1.2);
   - **максимальную относительную просадку**;
   - **число сделок** (нужно 200+, иначе результат случаен).
5. Оптимизация (по одному-двум параметрам за раз):
   - `RangePeriod` 10…60 шаг 10;
   - `ConfirmBars` 1…5;
   - `RewardRatio` 1.5…3.0 шаг 0.5;
   - `SessionStartHour` и `SessionEndHour`.
6. **Обязательно проверьте вне выборки.** Оптимизируйте на 2022–2024, затем без изменений прогоните 2025–2026. Если там результат развалился, найденные параметры — подгонка.
7. Потом минимум 1–2 месяца на демо или центовом счёте.

## Предварительная проверка идеи

Логику я проверил на Python на доступной выборке EURUSD H1: 5000 баров, апрель 2017 – февраль 2018, спред 2 пипса.

- С параметрами по умолчанию: 104 сделки, профит-фактор **1.04**, +2.5R, максимальная просадка 14.8R.
- По половинам выборки: 1.19 и 0.79.
- С подтверждением результат стабильно лучше, чем без него (вход сразу по свипу дал PF 0.8–0.9).
- Лучше всего вышло с `RangePeriod = 50` и сессией 7–20: PF 1.2–1.35, но это всего 70 сделок.
- При спреде 3 пипса результат уходит в минус.

Это **не доказательство прибыльности**. Выборка маленькая, и устойчивого перевеса на ней не видно. Решающим будет ваш тест на нескольких годах истории брокера.

## Параметры

| Параметр | По умолчанию | Описание |
|---|---|---|
| `RangePeriod` | 20 | Баров для поиска экстремумов (пул ликвидности) |
| `ConfirmBars` | 3 | Баров на подтверждение; 0 — вход сразу по свипу |
| `MaxSweepATR` | 2.0 | Прокол глубже N×ATR считается настоящим пробоем и пропускается |
| `MinWickRatio` | 0.0 | Минимальная доля фитиля в баре-свипе |
| `UseSession`, `SessionStartHour`, `SessionEndHour` | true, 8, 20 | Часы входа по времени сервера (можно через полночь) |
| `TrendMAPeriod`, `TrendTF` | 0, текущий | EMA-фильтр: BUY только выше EMA, SELL только ниже |
| `MaxSpreadPoints` | 30 | При большем спреде вход пропускается |
| `SLBufferATR` | 0.1 | Отступ SL за экстремум свипа |
| `MinSLPoints`, `MaxSLPoints` | 80, 800 | Допустимый размер SL в пунктах; для других символов подберите заново |
| `RewardRatio` | 2.0 | TP = риск × RR |
| `BreakevenAtR`, `BreakevenLockPoints` | 1.0, 10 | Безубыток при прибыли 1R с фиксацией 10 пунктов |
| `PartialCloseAtR`, `PartialClosePercent` | 0, 50 | Частичное закрытие (выкл.) |
| `TrailATR` | 0 | Трейлинг на расстоянии N×ATR после безубытка (выкл.) |
| `MaxBarsInTrade` | 0 | Выход по времени (выкл.) |
| `CloseOnFriday`, `FridayCloseHour` | true, 21 | Не держать позицию на выходных |
| `RiskPercent` | 1.0 | Риск на сделку, % от баланса |
| `FixedLot`, `MaxLot` | 0, 0 | Фиксированный лот или ограничение лота |
| `MaxDailyLossPercent` | 3.0 | После такого дневного убытка новых входов нет до завтра |
| `MaxDrawdownPercent` | 30.0 | Просадка эквити **всего счёта** от пика: позиция закрывается, торговля останавливается |
| `ECNMode` | false | Ставить SL/TP отдельным запросом после открытия |
| `Magic` | 220500 | Отличается от старого советника (111000), чужие ордера не трогаются |

После остановки по просадке торговля не возобновится сама. Чтобы сбросить защиту, удалите глобальную переменную `LSPro_<символ>_<Magic>_peak` (F3 в терминале). Защита считается по эквити всего счёта, поэтому её может включить и убыток других советников на том же счёте.
